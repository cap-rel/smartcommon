# Dépendances réexportées

smartcommon réexporte quelques briques de ses dépendances pour qu'une
application les importe au même endroit que les composants : toute la
bibliothèque lodash, les briques de routage de `react-router-dom`, la
fonction `toast` de `react-hot-toast` et le composant `Helmet` de
`react-helmet` sous le nom `Head`.

```js
import { Routes, Route, Navigate, Outlet, toast, Head, debounce, groupBy } from "@cap-rel/smartcommon";
```

## Symboles exportés

| Symbole | Origine | Rôle |
|---------|---------|------|
| `Routes`, `Route`, `Outlet`, `Navigate` | `react-router-dom` | Déclarer les routes de l'application sous le `Router` monté par `<Provider>`. |
| `toast` | `react-hot-toast` | Afficher une notification ; le `<Toaster>` est monté par `<Provider>`. |
| `Head` | `react-helmet` (`Helmet`) | Modifier le `<title>` et les balises de `<head>` depuis une page. |
| `_` | `lodash` | L'objet lodash complet (chaînage `_.chain`, `_.mixin`). |
| 300 fonctions lodash | `lodash` | Chaque fonction de lodash 4 sous son nom, listées ci-dessous. |

## Routage, notifications, titre de page

```jsx
import { Routes, Route, Navigate, RouteGuard, Head, toast } from "@cap-rel/smartcommon";

export const AppRoutes = () => (
  <Routes>
    <Route element={<RouteGuard requireAuth />}>
      <Route path="/" element={<Home />} />
    </Route>
    <Route path="/login" element={<Login />} />
    <Route path="*" element={<Navigate to="/" replace />} />
  </Routes>
);

const Home = () => {
  const onSave = async () => {
    await save();
    toast.success("Intervention enregistrée");
  };
  return (
    <>
      <Head><title>Interventions</title></Head>
      <button onClick={onSave}>Enregistrer</button>
    </>
  );
};
```

`react-router-dom` et `react-hot-toast` restent des dépendances externes
du paquet (`peerDependencies`) : l'application et smartcommon partagent la
même instance, donc le même contexte de routage et le même `<Toaster>`.
Pour les autres exports de `react-router-dom` (`useParams`, `Link`...),
importer directement depuis `react-router-dom`.

## Pièges

- Plusieurs noms lodash masquent un global du même nom une fois importés :
  `isNaN`, `isFinite`, `parseInt`, `toString`, `escape`. `isFinite("3")`
  de lodash vaut `false`, celui du navigateur `true`. Les importer sous un
  alias en cas de doute (`import { isNaN as _isNaN }`).
- `isEmpty` de lodash tient les nombres et les booléens pour vides : pour
  une règle `required` de formulaire, utiliser `isEmptyValue` (page
  Modules/Utils/Données).
- lodash fait partie du paquet : une application qui installe aussi lodash
  embarque deux copies. Importer depuis smartcommon ou depuis `lodash`,
  mais pas les deux pour un même usage d'état partagé (`uniqueId`,
  `templateSettings`, `mixin`).
- `Head` est `Helmet` de `react-helmet` sous un autre nom : la
  documentation de `react-helmet` s'applique telle quelle.

Aucun guide dédié dans `docs/` : la référence est `src/lib/deps/`. Le
routage protégé est décrit dans `docs/route-guard.md`.
